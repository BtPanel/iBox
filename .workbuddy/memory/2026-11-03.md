## 播放页「上滑退回首页」与返回键重复（修复）

- 现象：播放/详情页上滑直接回首页、不像崩溃；控制条显示时左上角有两个返回箭头。
- 根因：`VodPlaybackController.detailEmpty()` 在原实现里 `if (isFromCollect() || shouldFinish) finishVod()`，
  只要详情请求返回空且带 msg 就关掉整个播放页。上滑（单集影片上滑 = 刷新）或误触换源后都可能走到这里，
  表现就是「闪退回主页」。现改为只有 `!detailLoaded`（首次进入）才允许 finishVod，播放中一律走换源兜底。
- 返回键重复：`detailBack`（浮动的 40dp 圆底按钮）与控制条自带 back 都在左上角，且 `syncFullscreenUI`
  没同步它。现在 `showControl()` 隐藏 detailBack、`hideControl()` 按 `isFullscreen()` 恢复、
  `syncFullscreenUI()` 统一全屏隐藏；点击改为走 `onBack()`（全屏先退全屏）。
- `onFlingUp/onFlingDown` 增加 `isFinishing()/isDestroyed()/mVod/mEpisodeAdapter` 判空。
- 单测：`detailErrorWhilePlayingKeepsThePlaybackPageOpen`（反射设置 detailLoaded）。

## 播放页返回按钮 & GitHub 加速机制

- 播放页（竖屏详情）原本常驻一个浮动 `detailBack`，位置与控制条自带 back 重合 → 左上角两个箭头。用户要求删除：已从 `layout/activity_video.xml` 与 `layout-sw600dp/activity_video.xml` 移除，Java 侧 6 处显隐（enterFullscreen/exitFullscreen/showControl/hideControl/syncFullscreenUI/点击监听）一并删除，`bg_detail_back_button` + `detail_colors` 里两个 back 配色清理。退路只剩：点画面 → 控制条 back，或系统手势。commit 6b0e2ad。
- **GitHub 加速只对 GitHub 域名的资源生效**：内置加速前缀仅 2 个（`https://gh-proxy.com/`、`https://ghfast.top/`，见 catvod `GitHubUrl.ACCELERATORS`），候选链为 [自定义前缀… , gh-proxy, ghfast, 直连 raw, jsDelivr CDN] —— jsDelivr 是第 3 条线路（`cdn.jsdelivr.net/gh/owner/repo@ref/path`），这可能就是用户印象里的「3 个」。
- 生效范围：`RequestInterceptor`（OkHttp GET/HEAD 逐候选重试）+ `PyLoader`（爬虫/订阅配置加载）。只重写 host 属于 github.com / raw.githubusercontent.com / *.githubusercontent.com 的 URL；站点播放地址、非 GitHub 的直播 m3u 不会被改写。
