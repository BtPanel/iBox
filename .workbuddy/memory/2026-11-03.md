## 播放页「上滑退回首页」与返回键重复（修复）

- 现象：播放/详情页上滑直接回首页、不像崩溃；控制条显示时左上角有两个返回箭头。
- 根因：`VodPlaybackController.detailEmpty()` 在原实现里 `if (isFromCollect() || shouldFinish) finishVod()`，

  没同步它。现在 `showControl()` 隐藏 detailBack、`hideControl()` 按 `isFullscreen()` 恢复、

- `onFlingUp/onFlingDown` 增加 `isFinishing()/isDestroyed()/mVod/mEpisodeAdapter` 判空。

## 弹幕「发弹幕按钮无反应」修复

- **现象1**：播放页控制栏「发弹幕」图标点了连输入弹窗都不弹。
- **根因1**：`VideoActivity.onSendDanmaku()` 守卫 `if (!isShow() || !player().haveDanmaku()) return`，其中 `haveDanmaku()` = 已选中外部弹幕源。弹幕开关开但未选源时按钮可见却点了无反应。发弹幕本质是发本地即时弹幕（`sendNow→new Danmaku(text,0)`），不依赖外部弹幕源。修复：去掉 `haveDanmaku()` 守卫，只留 `isShow()`。
- **现象2（潜在）**：发送后弹幕可能不显示。`DanmakuView.sendNow(Danmaku)` 在 `released || !clock.started || viewWidth<=0` 时静默丢弃；`clock.started` 仅当 `DanmakuController.syncToPlayer` 里 player.isPlaying() 才被 `start()` 置 true，暂停或从未播放时发送的弹幕被丢弃但 Toast 仍提示「已发送」。
- **根因2 修复**：`DanmakuController.sendNow`（两个重载）新增 `ensureClockStarted()`——view 未 start 时用 `player.getCurrentPosition()` 调 `start()`，若 player 暂停/空则再 `pause()` 保持时钟不前进（start 会把 paused 置 false）。
- **注意**：`vendor/media3` 是 git 子模块（iBox-media3.git，本机 `.git` 未初始化所以 `git status` 看不到内部改动），但通过 settings.gradle `includeBuild` + `substitute lib-ui-danmaku` 实际参与编译，改动会生效。编译验证：`JAVA_HOME=jdk-27` + `ANDROID_HOME=.../Android/Sdk`，`:media3:lib-ui-danmaku:compileDebugJavaWithJavac` 通过。

## 搜索页闪退根因修复（6b76f36）
- 现象：手机搜索"加载一会后返回主页"。日志证据：11:27:52 `System.exit called, status: 0`（Chaquopy），搜索进行中进程自杀退出（has died: fg TOP），无 Java/Native 崩溃。

- 顺带：requests 改延迟导入，修 TV 端 ExceptionInInitializerError（No module named 'requests'，发生在 onDestroy→VodConfig.clear→BaseLoader 首次初始化 Python 时）。
- 排查注意：crash 缓冲区里大量 "Shutdown thread" SIGSEGV 是 uiautomator 自身崩溃，与 App 无关；模拟器 adb 连接极不稳定（每次 bash 调用 adb server 被回收），需单条命令内完成 start-server+轮询 device+操作；APK 输出路径是 app/build/outputs/apk/mobileArm64_v8a/（flavor 前缀连写）。
